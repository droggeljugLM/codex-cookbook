Codex 协作 Cookbook

面向真实工程任务的场景化协作手册：先判断局面，再复制菜谱，最后用验收闭环收口。

这份手册不是介绍“什么是好的 cookbook”，而是直接服务于你和 Codex 的协作过程。它把常见开发局面拆成可取用的菜谱：需求不清时怎么诊断，方案没定时怎么收敛，目标明确时怎么直接推进，修 bug 时怎么先复现，连续失败时怎么复盘换路，临近完成时怎么验收。

使用方式很简单：先在左侧找到你当前的场景，再进入对应菜谱。每个菜谱都包含适用场景、不适用场景、输入清单、可复制提示词、执行步骤、验收标准和常见误用。你不需要从头读完，只需要按场景取用。

和 Codex 协作的关键，不是写一个神奇提示词，而是把任务放进正确的工作流。

Codex 协作原则

先把协作方式定好，再让 Codex 进入具体任务。

1. 以边界换聚焦

明确这次做什么、不做什么、什么可妥协、什么不能妥协。边界越清楚，Codex 越不容易顺手扩散。

2. 以信息换准确

目标、背景、约束、错误现象、相关文件和验收方式越明确，返工越少。

3. 以文档换稳定

跨多轮任务不要只靠对话记忆。目标、方案、决策、进度、风险都应该沉淀为可更新记录。

4. 以验证换可信

不要停在“已经改了”。要用测试、最小复现、人工验收步骤或对比结果证明有效。

5. 先定模式，再给任务

同一个问题可以是诊断、计划、执行、复现、验收或复盘。模式不同，提示词结构也不同。

6. 长期建设与短期止血分开

长期模块优先可维护；线上应急优先恢复可用。不要把止血方案默认为最终方案。

7. 技术债先判断是否阻塞

阻塞当前正确性就处理；不阻塞就挂账，避免旁路治理吞掉主线任务。

8. 兜底方案必须显性化

临时解要说明正解、风险、局限和回收方式。不要让硬编码、吞错、绕过测试伪装成完成。

验证：通过【测试、最小复现、人工验收标准、日志、截图、对比结果】证明有效。
如果需要我确认，只集中提出最关键的 1 到 3 个问题，并按“问题、选项、利弊、推荐”格式给出。

组合菜谱

真实任务往往是多个菜谱的串联，而不是一个万能提示词。

方案讨论型

用“方案收敛与决策”先定义问题、比较候选方案、输出推荐路径，再进入直接推进。

直接开发型

用“主线清晰直接推进”限制范围、减少非关键确认，最后接“验收闭环”。

Bug 修复型

用“先复现再修复”稳定复现问题，修复后进入“验收闭环”，旁路问题进入“技术债挂账”。

中型项目型

先“方案收敛”，再“长期建设分阶段推进”，全程用“多轮协作文档化”维护状态。

推荐组合路径

  1. 问题不清：模糊局面诊断 → 方案收敛与决策 → 主线清晰直接推进 → 验收闭环。
  2. 修 bug：Bug 修复 → 验收闭环 → 技术债挂账。
  3. 连续失败：失败复盘与换路 → 方案收敛与决策 → 设置失败停点。
  4. 中型项目：长期建设分阶段推进 → 多轮协作文档化 → 阶段验收闭环。

一句话原则

先判断局面，再选择菜谱；先限定边界，再要求输出；先形成结果，再补验证；先记录共识，再跨轮推进。
